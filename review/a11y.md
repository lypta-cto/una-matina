# Una Mattina: accessibility audit (WCAG 2.2 AA)

Date: 2026-10-17 · Target: dev server `http://localhost:3001` · Read-only on app source.
Pages: `/`, `/services`, `/live-stations`, `/luxury-picnics`, `/bloom-cart`, `/how-we-work`, `/about`, `/inquire`, `/crepes`. Each page was checked at 1440 and 390 wide.

**Method.** I used Playwright 1.64 with Chromium, plus axe-core 4.14 injected with the tags `wcag2a/aa`, `wcag21a/aa`, `wcag22aa` and `best-practice`. I ran axe twice, once with `reducedMotion: reduce` and once with `no-preference`. For keyboard testing I did a full Tab pass and a full Shift+Tab pass on every page and width. At every stop I recorded the focus ring's colour and its contrast with the background, sampled 5 points with `elementFromPoint` to see whether anything covered the focused element, and checked for clipping and for the header's hidden state.

For contrast I computed values per text node and included `::before` fills, ancestor opacity and image overlap. Captions flagged by axe as "incomplete" were checked by hand. I checked reduced motion with `document.getAnimations()`, by scanning for opacity-0 elements while scrolling, and by logging network requests. I ran zoom and reflow tests at 640×512 (200 % of 1280), at 320×256, at 200 % text-only zoom on 1280, and with WCAG 1.4.12 text spacing at 1280 and 390.
The scripts are in the session scratchpad under `tools/` (`axe.cjs`, `kb.cjs`, `specific.cjs`, `contrast.cjs`, `motion.cjs`, `zoom.cjs`, `lib.js`).

> Note: while the audit was running, Nuxt's dev error overlay (`nuxt-error-overlay` / `<main class="mb-main">`) appeared twice for a moment. Another session was editing files and HMR triggered it. When it appeared, axe flagged `landmark-no-duplicate-main` on `/crepes`. I could not reproduce it afterwards, and it only happens in dev, so it is not listed as a finding.

## P0

### 1. `lang="__TOKEN__"` on every page (3.1.1 Language of Page)
- **Where:** all 9 pages, both widths. axe `html-lang-valid`, impact serious. The served HTML starts with `<html lang="__TOKEN__">`. The SSR head data in `.nuxt/dev/index.mjs` also has `site.url`, `site.name` and `site.defaultLocale` set to `"__TOKEN__"`, so the sitemap, robots and canonical data are affected too.
- **Cause:** `nuxt.config.ts` imports `site.config.ts` once, when the dev server starts. The dev server started at 22:03. At that point the starter values (`builder/starter/site.config.ts`, `lang: '__TOKEN__'`) were still in the file. `site.config.ts` was filled in at 22:04, and Nuxt does not reload its config when that file changes. `app.vue` reads the file at runtime, so the `<title>` is correct. That hides the problem.
- **Fix:**
  1. Restart `nuxt dev`, then confirm the result: `curl -s localhost:3001 | grep -o 'lang="[^"]*"'` should print `lang="en"`.
  2. To stop this happening again, add the following to `una-mattina/app/nuxt.config.ts`. It also belongs in `builder/starter/nuxt.config.ts`.
     ```ts
     export default defineNuxtConfig({
       // restart the dev server when the site facts change (nuxt.config imports them once)
       watch: ['site.config.ts'],
       …
     ```
  3. Before any deploy, run the existing `check-tokens` step against the **built** HTML (`.output/public/**/*.html`), not only against the source files.

### 2. Focus ring invisible on brown fields (2.4.7 Focus Visible, 1.4.11 Non-text Contrast)
- **Where:**
  - Every default-layout page, both widths: all 18 links in `SiteFooter` (nav and credit links). The ring is `#5B3A2E` on `#5B3A2E`, which is **1.00:1**.
  - `/crepes`: the photo credit links in the brown `.card-sec` ("DanielPenfield", "CC BY-SA 4.0") and the footer link "Una Mattina Events & Catering".
- **Cause:** `main.css` sets `:focus-visible { outline: 3px solid var(--ink) }`, and `--field-dark` is the same colour as `--ink`.
- **Fix:** add a focus-ring custom property and override it on dark fields. With the override, the ring is cream on brown at **9.45:1**.
  - `app/assets/css/main.css` (line 79):
    ```css
    :focus-visible { outline: 3px solid var(--focus-ring, var(--ink)); outline-offset: 3px; }
    ```
  - `app/components/SiteFooter.vue`:
    ```css
    .foot { …; --focus-ring: var(--on-field-dark); }
    ```
  - `app/pages/crepes.vue`:
    ```css
    .card-sec, .foot { --focus-ring: var(--on-field-dark); }
    .card { --focus-ring: var(--ink); } /* the cream card inside the brown band */
    ```

## P1

### 3. The sticky header covers the focused element (2.4.11 Focus Not Obscured, Minimum)
- **Where:** every default-layout page, both widths, when moving with Shift+Tab. Scrolling up brings the header back, and the browser scrolls only far enough to put the element at the top of the viewport, which is exactly where the header now sits. All 5 sample points of the focused element were covered by `header.head`. Examples:
  - `/` at 1440: "Start an inquiry" in the CloseCta, and the "DanielPenfield" and "CC BY-SA 4.0" credits.
  - `/` at 390: "Start with all three"; footer "About" and "How we work".
  - `/live-stations` at 390: all five `.sc__chip` buttons.
  - `/inquire` at 1440: the "Why is there no price list?" summary and the "Private home or backyard" chip.
- **Fix** (tested by injecting it: 0 covered stops on `/` at 1440 and 390, `/live-stations` at 390 and `/inquire` at 1440). In `app/assets/css/main.css`, inside `@layer base`:
  ```css
  html { scroll-padding-top: 76px; }                                  /* 56px bar + 2×8px padding + 4 */
  @media (min-width: 1100px) { html { scroll-padding-top: 96px; } }   /* 76px bar + 20 */
  ```
  This also makes in-page anchors such as `#counter` land below the header. `/live-stations` sets `.base { scroll-margin-top: 0 }`. Remove that line, or it can stay and simply have no effect.

### 4. `/live-stations` at ≥ 900 px: focus is lost to `<body>` (2.4.3 Focus Order, 2.4.7)
- **Where:** `LsStationList` sticky frame. Pressing Tab after "Set up your counter" focuses the credit link in layer 0, the crêpe photo. The browser scrolls the link into view. The IntersectionObserver then makes row 3 active, which sets `inert` on layer 0 while its link still has focus. `document.activeElement` becomes `BODY`. Going backwards, the frame's credit links are skipped completely.
- **Fix** in `app/components/LsStationList.vue`: don't swap layers while focus is inside the frame.
  ```ts
  const aside = ref<HTMLElement>()
  …
  io = new IntersectionObserver((entries) => {
    if (aside.value?.contains(document.activeElement)) return // never inert the layer a keyboard user is in
    for (const e of entries) { … }
  }, { rootMargin: '-45% 0px -45% 0px' })
  ```
  ```html
  <div ref="aside" class="lsl__aside">
  ```

### 5. Mobile menu: Escape leaves focus on `<body>` (2.4.3)
- **Where:** `SiteHeader`, at < 1100 px. The steps were: open the menu with Enter, Tab to "Services", press Escape. `aria-expanded` goes back to `false` and the sheet is hidden with `v-show`, but focus goes to `BODY`. The next Tab then lands on the page CTA. Opening with Enter or Space, `aria-expanded`, `aria-controls` and `aria-current` all work, and there is no trap because the menu is a push-down sheet, not a modal.
- **Fix** in `app/components/SiteHeader.vue`:
  ```ts
  const menuBtn = ref<HTMLButtonElement>()
  function onKey(e: KeyboardEvent) {
    if (e.key !== 'Escape' || !open.value) return
    const inSheet = !!document.getElementById('mobile-menu')?.contains(document.activeElement)
    open.value = false
    if (inSheet) menuBtn.value?.focus()
  }
  ```
  ```html
  <button ref="menuBtn" type="button" class="head__menu" …>
  ```
  The `watch(route.fullPath)` that closes the menu on navigation is fine as it is. NuxtLink moves focus as part of navigation.

### 6. `/crepes`: Instagram anchors without `href` (2.1.1 Keyboard, 4.1.2 Name, Role, Value)
- **Where:** `contact.instagram.url` is `''` (TBC), so `igHref` is `undefined`. That affects four anchors:
  - The hero "Follow on Instagram" `.btn-outline` looks like a button but is a plain generic element. It cannot be reached by keyboard, does nothing on click, and in the accessibility tree it is only `text: Follow on Instagram`.
  - The Visit section `@unamattina` link.
  - The footer "Instagram @unamattina" link.
  - The sticky bar "Instagram" (at 390). It has `tabindex="0"`, so it is a tab stop with no role that does nothing.
- **Fix** in `app/pages/crepes.vue`: render a link only when the URL exists.
  ```html
  <!-- hero -->
  <a v-if="igHref" :href="igHref" class="btn btn-outline" target="_blank" rel="noopener">Follow on Instagram<span class="sr-only"> (opens in a new tab)</span></a>
  <!-- visit -->
  <dd><a v-if="igHref" :href="igHref" class="link" target="_blank" rel="noopener"><Tbc note="Instagram handle">{{ contact.instagram.handle }}</Tbc></a><Tbc v-else note="Instagram handle">{{ contact.instagram.handle }}</Tbc></dd>
  <!-- footer -->
  <a v-if="igHref" :href="igHref" class="link" target="_blank" rel="noopener">Instagram <Tbc …>…</Tbc></a>
  <p v-else>Instagram <Tbc note="Instagram handle">{{ contact.instagram.handle }}</Tbc></p>
  <!-- bar -->
  <a v-if="igHref" :href="igHref" class="btn btn-primary" target="_blank" rel="noopener" :tabindex="showBar ? 0 : -1">Instagram</a>
  ```
  ```css
  .bar { grid-template-columns: repeat(auto-fit, minmax(0, 1fr)); }
  ```

### 7. Placeholder text 2.57:1 (1.4.3 Contrast, Minimum)
- **Where:** `/inquire`, both widths: `#f-area` ("e.g. Naples, Bonita Springs, Marco Island") and `#f-msg`. Tailwind preflight sets `::placeholder` to `currentColor` at 50 %, which gives ≈ `#AD988C`. That is **2.57:1** on cream and **2.49:1** on the focused surface.
- **Fix** in `app/components/InquiryForm.vue`:
  ```css
  .f__input::placeholder { color: var(--ink-muted); opacity: 1; } /* 6.41:1 cream, 5.79:1 surface */
  ```

### 8. Home rotator forces horizontal scroll on phones (1.4.10 Reflow)
- **Where:** `/`, `#home-stations`. When scroll progress reaches the last station, the plank shows "Cocktails & mocktails" with `white-space: nowrap`. The grid item `.stations__text` has `min-width: auto`, so it grows to fit and the document becomes wider than the viewport: `scrollWidth` 413 at 320, 415 at 360 and 424 at 390. At 640 there is no overflow.
- **Fix:**
  - `app/components/StationRotator.vue`:
    ```css
    .plank__t { white-space: normal; text-wrap: balance; }
    ```
  - `app/pages/index.vue`:
    ```css
    .stations__text { min-width: 0; }
    ```

### 9. `/crepes` card covers the photo caption (1.4.10, 1.4.4)
- **Where:** in `.card-sec`, the card has `margin-left: -80px`, so it overlaps the photo column, and the caption is the same width as the photo. Words hidden behind the card: "photo" and "of" at 1000 px, "a" at 900 px. At 200 % text-only zoom on 1280, "our" and "BY-SA", which is part of the licence link, are hidden. 900–1099 px is what a 1800–2200 px screen shows at 200 % zoom.
- **Fix** in `app/pages/crepes.vue`:
  ```css
  @media (min-width: 900px) { .card-sec__photo :deep(.found__cap) { padding-right: 96px; } }
  ```

## P2

### 10. `/crepes`: header and footer are inside `<main>`, and the skip link skips nothing (1.3.1, 2.4.1 best practice)
- **Where:** `layouts/crepes.vue` wraps the whole page in `<main id="main">`. As a result there is no `banner` landmark and no `contentinfo` landmark. The skip link goes to `#main`, and the next Tab lands on the logo, which is the very next control anyway.
- **Fix:**
  - `layouts/crepes.vue`: replace `<main id="main"><slot /></main>` with `<slot />`.
  - `pages/crepes.vue`: split the hero field so `<main>` starts at the hero.
    ```html
    <div class="crepes">
      <div class="hero-field"><Awning tone="yellow" size="m" /><header class="wrap nav">…</header></div>
      <main id="main">
        <div class="hero-field"><section id="crepes-hero" …>…</section></div>
        … intro, menu, card-sec, morning, visit …
      </main>
      <footer class="foot">…</footer>
      <div class="bar" …>…</div>
    </div>
    ```
    `.hero-field` already provides the apricot background, so both halves keep it.

### 11. Live regions that talk too much, or say the wrong thing (4.1.3 Status Messages)
- **`PillarExplorer`** (`/`): `aria-live="polite"` is on the whole `<ul>`. Each choice only adds or removes the sr-only text " (not included)", so a screen reader hears fragments like "(not included) (not included)" with no context.
  - Fix: remove `aria-live` from `.px__list` and add a short status line:
    ```ts
    const status = computed(() => { const n = examplePieces.filter(p => isOn(p.by)).length; return `${sel.value === 'all' ? 'All three' : pillars.find(p => p.id === sel.value)!.name}: covers ${n} of ${examplePieces.length} pieces of the example party.` })
    ```
    ```html
    <p class="sr-only" aria-live="polite">{{ status }}</p>
    ```
- **`InquiryForm` / `InqSummary`** (desktop): `<InqSummary :rows="rows" live />` announces every radio and checkbox the user just picked, so they hear their own choice twice. Fix: in `InquiryForm.vue` drop the prop, so it becomes `<InqSummary :rows="rows" />`.
- **`StationCounter`** (`/live-stations`): `aria-live` on `.sc__counter` reads the whole new sign, name plus note, on every add, and says nothing when a station is removed.
  - Fix: remove `aria-live` from `.sc__counter` and add a status line:
    ```ts
    const last = ref('')
    function toggle(id: string) { const s = stations.find(x => x.id === id)!; if (picked.value.includes(id)) { picked.value = picked.value.filter(x => x !== id); last.value = `${s.short} removed.` } else if (picked.value.length < MAX) { picked.value = [...picked.value, id]; last.value = `${s.short} added.` } }
    ```
    ```html
    <p class="sr-only" aria-live="polite">{{ last }} {{ picked.length }} of {{ MAX }} picked.</p>
    ```
- **`MarketStatus`:** this one is fine. Its text only changes when the market state changes, which the client checks once a minute.

### 12. Selected state shown by colour only (1.4.1 Use of Color, 1.4.11)
- **Where:**
  - `PillarExplorer`: a pressed row is apricot and an unpressed row is cream-deep, a difference of **1.66:1**. The text colour change (`ink` to `ink-deep`) is barely visible.
  - Checked form chips (`/inquire`) and pressed `.sc__chip` (`/live-stations`): the selected chip loses its ink border and becomes an apricot fill, which is **1.84:1** against cream.
- **Fix:** keep a dark edge and add a check mark with empty alt text, so it isn't read out.
  - `PillarExplorer.vue`:
    ```css
    .px__row[aria-pressed="true"] { box-shadow: inset 4px 0 0 var(--ink-deep); }
    ```
  - `InquiryForm.vue`:
    ```css
    .chip__in:checked + .chip__face { border-color: var(--ink); }
    .chip__in:checked + .chip__face::before { content: "✓" / ""; margin-right: 0.45em; font-weight: 600; }
    ```
  - `StationCounter.vue`:
    ```css
    .sc__chip[aria-pressed="true"] { border-color: var(--ink); }
    .sc__chip[aria-pressed="true"]::before { content: "✓" / ""; margin-right: 0.45em; }
    ```

### 13. StationCounter CTA looks disabled but still works (4.1.2, 1.4.3)
- **Where:** `/live-stations` with no station picked. `.sc__cta.is-off` sets `pointer-events: none; opacity: .5`, but the link stays in the tab order. Pressing Enter navigates to `/inquire?services=stations&stations=`, and the text renders at 50 % opacity.
- **Fix** in `StationCounter.vue`:
  ```html
  <NuxtLink v-if="chosen.length" :to="to" class="btn btn-primary sc__cta">Ask about {{ chosen.length > 1 ? 'these stations' : 'this station' }}</NuxtLink>
  <p v-else class="sc__cta-hint">Pick at least one station to ask about it.</p>
  ```
  Then delete `.sc__cta.is-off`.

### 14. Date input: weak keyboard focus indicator (2.4.7)
- **Where:** `/inquire` `#f-date`. In Chrome, keyboard focus lands on the date's internal sub-field, so `:focus-visible` doesn't match on the input itself and `outline: none` from `.f__input:focus` wins. The only cue left is the bottom border changing from line to ink and a cream-deep background.
- **Fix** in `InquiryForm.vue`:
  ```css
  .f__input[type="date"]:focus { outline: 3px solid var(--ink); outline-offset: 2px; }
  ```

### 15. Radio-group errors are not linked to the radios (3.3.1, 1.3.1)
- **Where:** `/inquire`. The `eventType` and `guests` radios get `aria-invalid="true"`, but the error text is only referenced from the `<fieldset aria-describedby>`, and support for that varies between screen readers. Focus does move to the first error, and the text inputs are linked correctly.
- **Fix** in `InquiryForm.vue`:
  - On each event-type radio: `:aria-describedby="errors.eventType ? 'e-type' : undefined"`.
  - On each guests radio: `:aria-describedby="errors.guests ? 'e-guests' : undefined"`.
  - Optionally, add `aria-required="true"` to `#f-name`, `#f-email` and `#f-area`. The visible "(required)" text already meets 3.3.2.

### 16. `/crepes` morning strip: focus ring clipped on the left and right (2.4.7)
- **Where:** `.morning { overflow: hidden }` cuts off the side edges of the 3 px ring on the full-width `ol.morning__strip`. Keyboard scrolling with ArrowRight works.
- **Fix** in `crepes.vue`:
  ```css
  .morning__strip:focus-visible { outline-offset: -3px; }
  ```

### 17. Text-spacing overflow at 390 (1.4.12 Text Spacing)
- **Where:** with 0.12 em letter spacing, 0.16 em word spacing and line-height 1.5 applied:
  - CloseCta planks ("ABOUT YOUR DAY" on `/` and `/about`) overflow by 13 px because `.plank { white-space: nowrap }`.
  - `/services` "PLANNING & COORDINATION" overflows by 3 px.
  - `/crepes` "CRÊPES" overflows by 17 px.
- **Fix:**
  - `app/components/CloseCta.vue`:
    ```css
    @media (max-width: 599px) { .plank { white-space: normal; } }
    ```
  - `app/assets/css/main.css`. This only breaks a word when it would otherwise overflow, and does not change min-content sizing:
    ```css
    .sign-xl, .sign-l, .sign-m { overflow-wrap: break-word; }
    ```
  - `crepes.vue`:
    ```css
    .hero__word { overflow-wrap: break-word; }
    ```

### 18. Infinite "drift" on the /crepes hero image (2.2.2 Pause, Stop, Hide)
- **Where:** `ConceptImage` with the `drift` prop: `drift 18s infinite alternate`, which starts automatically and has no pause control. Reduced motion is handled correctly. The same pattern exists in `HeroVideo` `.is-still .hv__poster` (24 s infinite), but that only runs when there is no video.
- **Fix:** either remove `drift` from the `/crepes` hero `<ConceptImage …>`, or make the motion finish within 5 s.
  - `ConceptImage.vue`:
    ```css
    .is-drift { animation: drift 5s var(--ease-out) 1 both; }
    ```
  - `HeroVideo.vue`:
    ```css
    .is-still .hv__poster { animation: hv-scale 5s var(--ease-out) 1 both; }
    ```

### 19. Links that open a new tab don't say so (G201, advisory; 3.2.5 is AAA)
- **Where:** 8 to 18 `target="_blank"` links per page, in `FoundPhoto`, the `HeroVideo` credit and `SiteFooter` credits, plus the `/crepes` "Find us ↗", "Directions ↗" and "Get directions ↗" links. On /crepes the ↗ is correctly `aria-hidden`, but nothing replaces it for screen readers.
- **Fix:** append the following inside each of those anchors:
  ```html
  <span class="sr-only"> (opens in a new tab)</span>
  ```
  Alternatively, drop `target="_blank"` from the credit links.

### 20. Duplicate `id="sign-base"` on `/about` (robustness)


### 21. Language of parts (3.1.2)
- **Where:** `/crepes` "Buongiorno," is Italian.
- **Fix:** `<p class="statement hero__hello" lang="it">Buongiorno,</p>`.

### 22. Text-only zoom: some headings don't grow (1.4.4, advisory)
- **Where:** page zoom at 200 % passes. With text-only zoom, headings whose size is capped in pure `vw` stay the same size:
  - home `.stations__title` 67→67 px
  - `.plan__title` 52→52
  - `/live-stations` h1 115→115
  - CloseCta 67→67
  - `/crepes` `.hero__word` 141→141
  - `.rule__statement` 34→34
- **Fix:** add a `rem` term to the cap so it scales with text-only zoom.
  - Example: `min(var(--step-4), 5.2vw)` → `min(var(--step-4), calc(4.2vw + 1rem))`.
  - `how-we-work.vue`: `.rule__statement { font-size: clamp(1.375rem, 0.95rem + 1.5vw, 2.25rem); }`.

### 23. The TBC tag reads into the sentence
- **Where:** for example, "We reply within two business days to confirm ." on `/inquire`, and "…at the Sunday market to confirm" in MarketStatus.
- **Fix** in `Tbc.vue`:
  ```html
  <span class="tbc__tag"><span class="sr-only">(</span>to confirm<span class="sr-only">)</span></span>
  ```

### 24. Headroom: unhide on focus, not only on scroll (hardening for 2.4.11)
- **Where:** `SiteHeader` only clears `hidden` inside `onScroll`. In testing, Shift+Tab into the hidden header did reveal it, but only because the browser happened to scroll.
- **Fix:** `<header ref="root" class="head" … @focusin="hidden = false">`.

- **Focus ring contrast on other fields:**

  | Field | Ring contrast |
  |---|---|
  | cream | 9.45 |
  | cream-deep | 8.54 |
